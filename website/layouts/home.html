A deliberate workflow

From desired state to reviewed action.

Preparation observes your hosts.
Apply changes them with your agreement.

  1. 01

    Define

    Assign ordered services to hosts in a YAML inventory.

  2. 02

    Diff

    Render templates and compare the desired state with the target.

  3. 03

    Review

    Inspect file changes, operations, and execution order.

  4. 04

    Apply

    Confirm the plan and execute its prepared inputs.

Prepared inputs. Explicit execution.

The plan is the handoff.

Prepare once, apply what you reviewed.

Saved JSON holds executable operations and rendered file contents. Apply uses those inputs without rereading inventory, templates, or secret sources, or recalculating the diff. How saved plans work →

Use the host access you already have.

SSH uses your system OpenSSH client, current client configuration, keys, and agent. Sudo is explicit and noninteractive. Host execution is bounded; services stay ordered within each host. SSH and parallel apply →

Continue with the same plan.

Progress is saved per task. A new explicit apply skips successful tasks and retries unfinished ones. A failed host blocks its later tasks while other hosts continue. Failure and continuation →

Keep sensitive changes out of the display.

Local YAML secret sources resolve during preparation. Using a secret hides the entire file diff. Executable plans retain the real content and must stay private. Secrets and sensitive files →
